# Fase 4 — Gestão de Alunos: Plano de Implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar a gestão completa de alunos por academia (cadastro, consulta, edição, status, documentos, contatos, endereço, vínculos com unidades, transferência, histórico e observações), com isolamento multi-tenant e UI responsiva.

**Architecture:** Módulo modular `com.gymsaas.student` em Clean Architecture (`domain`, `application`, `infrastructure`, `presentation`). Casos de uso explícitos orquestram regras; portas de repositório isolam JPA; controllers só traduzem HTTP. Persistência PostgreSQL com RLS e FKs compostas `(tenant_id, id)`. Frontend Next.js em MVVM com ViewModels por tela.

**Tech Stack:** Java 21, Spring Boot 3.5, Spring Security/JWT, Spring Data JPA, Flyway, PostgreSQL 16, JUnit 5, Mockito, Testcontainers, Next.js 14 App Router, TypeScript, Tailwind.

**Spec:** `docs/specs/2026-11-12-phase4-plan.md` (decisões aprovadas) + prompt da Fase 4.

## Global Constraints

- `tenant_id` **sempre** vem de `TenantContext.requireTenantId()`; nunca de header/body.
- Toda tabela filha usa FK composta `(tenant_id, student_id)` e `UNIQUE (tenant_id, id)` no pai.
- RLS habilitada em todas as tabelas novas; runtime role `gymsaas_app` é `NOSUPERUSER`/`NOBYPASSRLS`.
- Migrations: última aplicada é **V7**; criar **V8** e **V9**, nunca editar anteriores.
- Status cadastral: `PENDING`, `ACTIVE`, `INACTIVE`, `BLOCKED`, `ARCHIVED` (não confundir com financeiro/matrícula).
- CPF: normalizar para 11 dígitos, validar dígitos verificadores, único por tenant entre alunos não excluídos.
- Matrícula: `AAAA` + 5 dígitos (`202600001`), contador atômico por tenant/ano.
- Vínculos: vários ativos, exatamente um principal; transferência encerra o principal e abre o novo.
- `students` não tem `branch_id`; vínculo vive em `student_branch_assignments`.
- CPF nunca em log; documentos mascarados por padrão. Valor completo exige `students:read_sensitive`.
- Permissões plurais `students:*`; manter compatibilidade com as singulares `student:*` existentes.
- Sem exclusão física de aluno: `deleted_at` (soft delete) e histórico preservado.
- Frontend: não carregar todos os alunos; busca/filtros/paginação/ordenação server-side; skeleton e vazio.
- Java: `JAVA_HOME=/tmp/opencode/tools/jdk21`, `-Dmaven.repo.local=/tmp/opencode/m2repo`.
- Não implementar Fase 5, pagamentos, biometria, reconhecimento facial ou Control iD.

## Review Focus

- CPF duplicado no mesmo tenant sob concorrência → uma requisição vence, a outra recebe `409 CPF_ALREADY_EXISTS`.
- Matrícula gerada em paralelo → nenhuma colisão e todas as matrículas únicas.
- Aluno de outro tenant acessado por UUID → `404 STUDENT_NOT_FOUND`, nunca vazamento de existência.
- Documento sensível sem permissão → valor mascarado; `read_sensitive` → valor completo.
- Transferência de unidade → histórico antigo preservado e exatamente um vínculo principal ativo.
- Data de nascimento futura / status inválido / e-mail inválido → `400` com detalhes de campo.
- Paginação acima de 100 / sort não permitido → tamanho limitado e ordenação segura.
