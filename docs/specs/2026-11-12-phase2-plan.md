# Plano da Fase 2 — Implementação da Infraestrutura

> **Pré-requisito**: Validação e aprovação de todos os documentos da Fase 1 (arquitetura, banco, Control iD, gateway, segurança, ADRs).

---

## Objetivo da Fase 2

Implementar a **infraestrutura base** do sistema:
- Backend Spring Boot (monólito modular) rodando local + Docker
- Frontend Next.js com Design System + Auth
- Banco PostgreSQL com Flyway migrations + RLS
- Gateway Local (esqueleto + comunicação Control iD mock)
- CI/CD pipelines + Observabilidade

**Duração estimada**: 4-6 sprints (2-3 semanas cada) = 8-18 semanas
**Time sugerido**: 2 backend, 1 frontend, 1 DevOps/Infra, 1 QA

---

## Sprint 1: Fundação Backend (Semanas 1-2)

### Entregáveis
- [ ] Projeto Spring Boot 3.2+ multi-módulo (Maven)
- [ ] Configuração base: Java 21, Spring Boot 3.2, Spring Security 6, Spring Data JPA, Querydsl
- [ ] Docker Compose dev: PostgreSQL 16, Redis 7, RabbitMQ 3.12, Mailhog, MinIO (S3 mock)
- [ ] Flyway baseline + migrations V1_0_0 a V1_9_0 (schema completo Fase 1)
- [ ] Testcontainers config (PostgreSQL, Redis, RabbitMQ)
- [ ] CI Pipeline: Build → Test (unit + integration) → Docker Build → Push registry

### Critérios de Aceite
- `./mvnw verify` passa (testes + spotbugs + checkstyle)
- `docker compose up -d` sobe stack completa em < 2 min
- Flyway `migrate` aplica sem erro em DB limpo
- Health endpoint `/actuator/health` retorna UP com checks: db, redis, rabbitmq

## Sprint 2: Multi-Tenancy + Auth + RBAC (Semanas 3-4)

### Entregáveis
- [ ] `TenantContextHolder` + `CurrentTenantIdentifierResolver` (Hibernate)
- [ ] RLS Policies no PostgreSQL (todas tabelas multi-tenant)
- [ ] Spring Security: JWT (access + refresh), OAuth2 Resource Server, Method Security
- [ ] Roles/Permissions seed: `SAAS_ADMIN`, `TENANT_ADMIN`, `BRANCH_MANAGER`, `RECEPTIONIST`, `STUDENT`
- [ ] Endpoints: `/auth/login`, `/auth/refresh`, `/auth/me`, `/auth/mfa/*`
- [ ] Auditoria automática: `@EntityListeners(AuditingEntityListener.class)` + `AuditLogRepository`

### Critérios de Aceite
- Login retorna JWT + refresh token (HttpOnly cookie)
- `@PreAuthorize("hasPermission(#id, 'student:read')")` funciona
- Query `Student` automaticamente filtra por `tenant_id` (RLS + Hibernate filter)
- Tentativa cross-tenant retorna 403/404
- Audit log registra CREATE/UPDATE/DELETE com before/after

## Sprint 4: Controle de Acesso + Biometria (Semanas 8-10)

### Entregáveis
- [ ] Módulos: `gymsaas-access`, `gymsaas-device`

## Sprint 5: Adapter Control iD + Gateway Esqueleto (Semanas 11-13)

### Entregáveis
- [ ] Módulo `gymsaas-controlid`: `ControlIdApiClient`, `ControlIdObjectMapper`, DTOs
- [ ] Mock Server Control iD (WireMock/Testcontainers) para testes de integração
- [ ] Gateway App (projeto separado): Spring Boot 3.2 + SQLite (SQLCipher) + H2
- [ ] `ControlIdMonitorServer` (endpoints `/dao`, `/catra_event`, `/operation_mode`, `/device_is_alive`)
- [ ] `ControlIdPushClient` (polling `/push` + transaction executor)
- [ ] `SyncOrchestrator` + `AccessPolicyCache` (double-buffered)
- [ ] mTLS config (keystore/truststore) + bootstrap script

### Critérios de Aceite
- Mock Server responde a todos endpoints mapeados no doc Fase 1
- Gateway recebe eventos Monitor → persiste SQLite → publica EventBus
- Gateway executa comandos Push → retorna resultado → ack
- Sync incremental (checksum diff) funciona
- Offline: fila eventos persiste; replay ao reconectar

## Sprint 8: Hardening + Observabilidade + Deploy (Semanas 20-22)

### Entregáveis
- [ ] **Segurança**: Rate limiting (Bucket4j), CSP, Security Headers, Dependency Check (OWASP)
- [ ] **Observabilidade**: Prometheus + Grafana dashboards (RED metrics, Business KPIs)
- [ ] **Logging**: JSON structured + correlation IDs + Loki/Grafana
- [ ] **Tracing**: OpenTelemetry + Jaeger (distributed tracing SaaS ↔ Gateway)
- [ ] **Chaos Testing**: Network partition, Device reboot, SaaS downtime (Testcontainers + Toxiproxy)
- [ ] **Deploy**: Kubernetes manifests (Helm) ou Docker Swarm; Blue-Green; Rollback < 5 min
- [ ] **Documentação**: RUNBOOK.md, API docs, Troubleshooting guide

### Critérios de Aceite
- Pipeline: Build → Test → Security Scan → Deploy Staging → Smoke Tests → Deploy Prod
- MTTR < 30 min (rollback automático se health check falha)
- Alertas: Gateway offline > 5min, Sync falha 3x, Certificate < 30d, Disk > 80%
- Load test: 1000 req/s backend, 500 concurrent users frontend, 100 gateways simulados

## Riscos Fase 2 e Mitigações

| Risco | Prob. | Impacto | Mitigação |
|-------|-------|---------|-----------|
| Complexidade Control iD > esperado | Média | Alto | Mock server abrangente; spikes técnicos sprint 5; parceria suporte Control iD |
| Performance RLS + particionamento | Baixa | Médio | Load test sprint 8; EXPLAIN ANALYZE contínuo; índices compostos |
| Gateway offline prolongado em campo | Média | Alto | Testes chaos sprint 8; alertas proativos; runbook recuperação |
| LGPD compliance gaps | Baixa | Crítico | Revisão jurídica sprint 4; testes automatizados DSR |
| Timebox estourado | Média | Médio | Priorização MoSCoW; scope fixo por sprint; buffer 20% |
